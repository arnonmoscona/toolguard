# toolguard 0.4.1 -- 2026-07-18

This is the first release notes entry for toolguard. It covers everything since `0.3.1`
(tagged `before-TOO15`) -- essentially all of TOO-15, a large effort. This is a summary, not
a full changelog; the documentation itself (see `README.md` and `docs/`) is the source of
truth for how everything actually works today.

## Guided install and uninstall

- New agent-driven, step-by-step install runbook ([`docs/install.md`](../docs/install.md))
  and matching uninstall runbook ([`docs/uninstall.md`](../docs/uninstall.md)): scope and
  option selection, `uv tool install`, hook registration, validation, an optional first
  migration/audit/maintenance pass, and takeover-mode setup -- with every action journaled to
  `~/.toolguard/install-journal.md` for a reliable, reversible rollback.
- New `toolguard-install` CLI helper with dedicated subcommands (`init-state`,
  `write-config`, `register-hooks`, `seed-self-perms`, `enable-takeover`, `journal`,
  `discover-projects`, `install-skills`, `seed-hard-deny`, `skills-status`) so install/uninstall
  steps are mechanical, journaled, and reversible instead of ad hoc agent-driven edits.
- Hardened through more than nine rounds of real-machine install testing, fixing real bugs
  along the way: backup-filename collisions, a recurring migration target-level bug, crash
  reports on stray invocations, `CLAUDE_SETTINGS_PATH` footgun detection, and more.
- New self-integrity `[hard_deny]` protection so `~/.toolguard/` cannot be deleted by an
  in-band `rm`/`find -delete` while toolguard's own config is live (a known, accepted gap:
  this protection does not currently survive a full uninstall -- tracked separately).

## Security audit and maintenance tooling

- New `toolguard-security-audit` skill and `toolguard-audit` CLI: a deterministic risk
  analyzer (over-broad allows, brittle secret protections, unanchored regexes, takeover-mode
  misconfiguration) plus an optional deeper AI-assisted pass and a safety-floor probe.
- New `toolguard-maintenance` skill and `toolguard-maintain` CLI: a guided, multi-pass,
  conversational rule clean-up -- redundancy/consolidation detection, mis-levelled rule
  promotion, evidence from real usage (`--corpus`, harvested from logs and Claude Code
  transcripts), and certification (parses, passes the audit, replays cleanly against your own
  history) before anything is applied. A persistent decision ledger keeps periodic runs quiet
  about anything already settled. Nothing is ever changed without explicit, per-item consent.

## Configuration and semantics

- `no_match_fallback` clarified as a top-level `toolguard_hook.toml` key (the `[takeover_mode]`
  nested form is now an explicit legacy alias), defaulting to `ask`.
- `allow_with_warning` documented as the deliberate choice for running toolguard underneath
  Claude Code's own auto-accept/bypass-permissions modes (new
  [`docs/auto-mode.md`](../docs/auto-mode.md)), not a general recommendation.
- `[config_sync]` auto-migration (`auto_migrate`), with manual `toolguard-migrate` covering
  `--dry-run`, `--no-sort`, and `--backup-dir`.

## Documentation

- Full two-pass documentation audit: fact-accuracy against source code (several stale or
  incorrect doc claims found and fixed) and audience/structure review (impatient-human,
  agent, and diligent-human readers).
- New [`docs/agent-map.md`](../docs/agent-map.md): a heading-level index across every doc plus
  a curated question-and-pointer list for common lookups, wired into the existing `AGENTS.md`
  and `llms.txt` agent-discovery conventions.
- New `/documentation-review` command (`.claude/commands/documentation-review.md`) and a
  `CLAUDE.md` pre-push checklist item, to keep the documentation set (especially
  `agent-map.md`) from drifting out of sync going forward.
- `docs/quickstart.md` rewritten into a genuine one-pager pointing at the guided install and
  the skills instead of duplicating manual setup steps.

## Distribution

- `toolguard-update-check` for both git and local/editable installs (manual, throttled-alert,
  and opt-in auto-update patterns documented in `docs/configuration.md`).
