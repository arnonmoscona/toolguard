# toolguard 0.5.0 -- 2026-07-23

Covers TOO-30: an optional split-file user-level configuration directory, plus the
consolidated test isolation this ticket motivated. Documentation-only fixes found during
this ticket's own review are included too.

## Split user-level rules directory

- New optional discovery step: toolguard scans `$XDG_CONFIG_HOME/toolguard/rules/`
  (defaulting to `~/.config/toolguard/rules/` when unset or empty) for any number of
  `*.toml`/`*.json` files, so a large, self-contained rule set (e.g. `docs/gh-cli-rules-example.toml`'s
  ~60 `gh` CLI rules) no longer has to be pasted into a single `toolguard_hook.toml`. See
  [Split user-level rules directory](../docs/configuration.md#configuration-hierarchy).
- Every file merges into the existing **user level** (least-specific tier) -- not a new
  hierarchy tier -- so normal more-specific-wins / deny-wins-within-a-level resolution
  applies across the combined set exactly as it does today. `[hard_deny]`, extended
  syntax (`[regex]`/`[glob]`/`[native]`), and `toolguard-migrate --dry-run`'s
  duplicate/superset detection all pick up rules-directory files automatically, with no
  special-casing needed anywhere else in the codebase.
- Files are restricted to `[permissions]`/`[hard_deny]` sections only (not scalars like
  `governed_tools` or `no_match_fallback`); an unexpected top-level key is reported as an
  error naming the specific file, without blocking that same file's valid content from
  loading.
- Each matched rule's resolution-log provenance names the specific file it came from
  (e.g. `[user: ~/.config/toolguard/rules/gh.toml]`), not just "user level" generically.
- Hardening found during this ticket's own review: a syntactically-valid-but-wrong-shape
  config file (e.g. a JSON array instead of an object) previously crashed the whole hook
  for every command; it's now skipped with a warning instead, like any other unparseable
  file. Fixes both the new rules-directory path and a pre-existing latent gap in the
  primary `~/.claude/toolguard_hook.toml` path.

## Test isolation

- New shared `ConfigIsolationMixin` (`test/unit/_config_isolation.py`) consolidates how
  the test suite isolates `Path.home()`, `find_project_root()`, and
  `XDG_CONFIG_HOME`/`CLAUDE_SETTINGS_PATH` from the real machine running the tests --
  this repo dogfoods toolguard on itself, so a real `~/.claude/toolguard_hook.toml` could
  otherwise silently leak into test results (it already had, causing two real test
  failures found and fixed during this retrofit). Retrofitted across all 8 test files
  that exercise config discovery; ad hoc, inconsistent isolation patterns removed.
- New `test/unit/CLAUDE.md`: a checklist for keeping new/edited tests isolated correctly
  going forward, plus a pre-push audit for new isolation gaps as production code evolves.

## Documentation

- Fixed 8 broken self-referencing anchor links (in `agent-map.md` and
  `technical-notes.md`) caused by an underscore-stripping bug in a prior TOC-generation
  pass.
- Added `XDG_CONFIG_HOME` to `configuration.md`'s environment-variables reference table
  and cross-linked the new rules-directory feature from `agent-guides.md`'s "share rules
  across many projects" recipe and `agent-map.md`'s Q&A list.
