# Predicted touch set -- ticket 77 (leading env assignment)

Design being predicted (given to me, not in the ticket): strip a leading `VAR=value` assignment for `deny`, `hard_deny` and `ask` matching by adding the stripped spelling as an **additional variant alongside the raw one**; for `allow`, match raw only **except** for assignment names in a **configured safe-list**.

That design has three distinct cost centres, and my set is built from them rather than from the defect location:

1. **Variant generation** -- something must produce `{raw, stripped}` and hand both to the matcher.
2. **List-asymmetric matching** -- the four lists no longer share one matching call; allow takes a different path, and it needs the safe-list value in hand.
3. **Config plumbing for the safe-list** -- a new configurable key must be typed, loaded, validated, defaulted, documented, and reachable from the matcher (which sits in the engine layer, below config, so it arrives as a parameter, not an import).

Item 3 is the one I expect to dominate the file count. Item 2 is the one I expect to dominate the difficulty.
